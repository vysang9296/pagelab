# Folder Lab - Page Lab 연계 기능 설계서 (Design Specification)

이 문서는 Folder Lab의 다양한 소스 영역(로컬 탐색기, 실시간 작업창, 가상 스테이징, 심층 검색 결과)에서 수집 및 발견한 문서를 Page Lab의 편집 영역으로 즉시 전송하여 연계 작업을 진행하기 위한 설계 스펙을 정의합니다.

## 1. 목적 (Goal)
두 개별 워크스페이스(Page Lab과 Folder Lab) 간의 데이터 흐름을 연결하여, Folder Lab에서 수집되거나 심층 검색을 거친 문서 파일들을 별도의 물리 파일 경로 추적이나 이중 업로드 없이 원클릭으로 Page Lab으로 전송하여 즉각적인 분할, 결합 및 정렬(Chop Chop) 작업을 이어가도록 연계 편의성을 제공합니다.

---

## 2. 상세 요구사항 및 처리 흐름 (Requirements)

### 2.1 대상 소스 영역 및 전송 데이터 정의
Folder Lab의 모든 우클릭 이벤트는 공통 UI 팝업 구조(`flShowContextMenu`)를 공유하므로, 각각의 `treeType`에 따라 적절한 절대 파일 경로(`path` 또는 `paths` 목록)를 추출해 매핑합니다.

1. **로컬 탐색기 (`local`) / 실시간 작업창 (`real`)**: 
   - 대상 파일이 디렉토리가 아니고 지원하는 문서 포맷(`.pdf`, `.hwp`, `.hwpx`)인 경우 메뉴가 노출됩니다.
   - 단일 파일의 디스크 절대 경로(`path`)를 배열 형태로 수집합니다.
2. **심층 검색 결과 목록 (`search`)**:
   - 검색 아이템 우클릭 시 `treeType === 'local'`로 전달되며, 대상 파일의 물리 경로(`res.path`)를 단일 원소 배열로 수집합니다.
3. **가상 스테이징 (`staging`)**:
   - **가상 파일 노드**: 가상 노드 객체에 포함된 실제 파일 절대 경로(`path`)를 단일 원소 배열로 수집합니다.
   - **가상 폴더 노드**: 가상 폴더 내부의 모든 자식 노드들을 **재귀적으로 순회(Recursion)**하여, 디렉토리가 아닌 가상 파일들이 가지고 있는 모든 실제 파일 절대 경로(`path`)들을 배열로 모아서 일괄 전송(Batch Import)을 지원합니다.

### 2.2 UI 마크업 및 노출 정책
- **컨텍스트 메뉴**: Folder Lab 공통 컨텍스트 메뉴(`#fl-context-menu`) 최하단에 `📄 Page Lab에서 편집하기` 메뉴 항목을 추가합니다.
- **노출 트리거**: 우클릭한 타겟의 확장자가 문서 포맷이거나, 혹은 가상 스테이징 내의 폴더 노드인 경우에만 이 항목을 활성화(`display: block`)합니다.

### 2.3 프론트엔드 - 백엔드 파이프라인 연계
- 클릭 시 `flExecuteContextMenu('open_pagelab')` 액션이 동작합니다.
- 수집된 절대 경로 목록(`paths`)이 비어있지 않다면, 화면에 로딩 인디케이터(`showLoading`)를 실행하고, 백엔드 API인 `pywebview.api.process_files(paths)`를 비동기로 호출합니다.
- 파일 로드 및 썸네일 구축이 성공적으로 완료되면, `tab_manager.js` 내의 `switchTab('pagelab')` 함수를 호출하여 화면을 Page Lab으로 즉시 탭 전환하고 로딩바를 해제합니다.

## 3. 검증 계획 (Verification Plan)
1. **검색 결과 연계 검증**: 심층 검색 후 결과 파일 우클릭 -> `Page Lab에서 편집하기` 시 정상 로드 및 탭 전환 검증.
2. **로컬/실시간 파일 연계 검증**: 좌측 탐색기 및 실시간 작업창 내의 단일 파일 전송 검증.
3. **가상 폴더 일괄 연계 검증**: 여러 문서들이 담긴 가상 폴더 우클릭 -> Page Lab 전송 시 내부의 모든 문서가 빠짐없이 Page Lab 원본 목록에 추가되는지 검증.
